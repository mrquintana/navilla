# Internationalization (i18n)

Navilla supports two languages. The active language is determined automatically on first visit and can be changed at any time via the language switcher.

| Code | Language |
|------|----------|
| `en_US` | English (default) |
| `es_MX` | Spanish |

## Stack

- **[react-i18next](https://react.i18next.com/)** — React bindings for i18next
- **[i18next-browser-languagedetector](https://github.com/i18next/i18next-browser-languageDetector)** — pluggable language detection
- Locale files in `src/locales/en_US.json` and `src/locales/es_MX.json`

## Language detection

When a user visits Navilla for the first time (no stored preference), the app picks the language automatically using two browser-native signals — no network request involved.

### Detection order (production)

```
1. localStorage        ← user's explicit choice, always wins
2. timezoneLocale      ← custom detector (see below)
3. fallback: en_US
```

In **development**, only `localStorage` is used so you can freely test both languages via the switcher without the automatic detection overriding you.

### timezoneLocale detector

Implemented in `src/lib/geolocation.ts` → `detectLanguage()`.

```
Intl.DateTimeFormat().resolvedOptions().timeZone
  → map to country code (e.g. America/Mexico_City → MX)
  → if country is Spanish-speaking → es_MX

navigator.language
  → if starts with 'es' (es, es-MX, es-419, es-ES…) → es_MX

otherwise → en_US
```

Timezone is checked first because it reflects where the device actually is, which is more reliable than the browser's language setting for location-based decisions (e.g. a traveller in Mexico with an English browser still gets Spanish).

### Spanish-speaking countries recognised

`MX ES AR CO CL PE VE EC BO PY UY CR DO GT HN NI PA SV CU PR GQ`

## Persisting user preference

When a user changes language via `LanguageSwitcher`, two things happen:

```ts
i18n.changeLanguage(newLang);
localStorage.setItem('navilla_language', newLang);
```

On the next visit, `localStorage` is checked first, so the choice is remembered indefinitely.

## Locale files

All UI strings live in the locale files. Both must be updated whenever new UI text is added.

```
src/locales/
  en_US.json   ← source of truth
  es_MX.json   ← Spanish translations (or English placeholder if untranslated)
```

### Adding a new string

1. Add the key and English value to `en_US.json`
2. Add the same key with the Spanish translation (or the English value as a placeholder) to `es_MX.json`
3. Use it in a component via `useTranslation`:

```tsx
import { useTranslation } from 'react-i18next';

function MyComponent() {
  const { t } = useTranslation();
  return <p>{t('my.key')}</p>;
}
```

## Components

### `LanguageSwitcher`

`src/components/LanguageSwitcher.tsx`

A `<select>` dropdown that lists supported languages, calls `i18n.changeLanguage()`, and persists the choice to `localStorage`. Rendered in the profile settings page.

### `ContentPage`

Static footer pages (About, Help, Privacy Policy, etc.) are not internationalised — they are English-only prose. The `ContentPage` component renders them without i18n keys.

## Dev utilities

Force a language in development by setting `navilla_language` in `localStorage`:

```js
// Browser console
localStorage.setItem('navilla_language', 'es_MX');
location.reload();
```

Or use the language switcher in the profile settings page.

## Country detection (signup form)

`detectCountry()` (also in `src/lib/geolocation.ts`) uses the same timezone + locale signals to pre-fill the **country dropdown** on the signup form. It returns `{ countryCode }` and is called once during state initialisation:

```ts
const [country, setCountry] = useState(
  () => detectCountry()?.countryCode ?? ''
);
```
